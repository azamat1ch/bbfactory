# ACP model selection — deviations journal (2026-09-19)

Scope: `packages/provider-bridge-acp/**` and this file. Fix `selectAcpNativeModel`
in `src/bridge/bridge.ts` so an explicitly requested ACP-native model is either
established and confirmed, or session construction fails before `session/prompt`.
Never silently run the agent's current/default model.

## Entry 1 — task intake (before changes)

- Expected: requested native model id is established via `session/set_config_option`
  (model config option) or `session/set_model`, or thread start fails clearly.
- Observed: `selectAcpNativeModel` only calls `session/set_model` when the
  requested id is present in `models.availableModels` (and no model config
  option exists). If the agent advertises a different/empty catalog — or no
  model surface at all — selection is skipped silently and the prompt runs on
  the agent's current model.
- Evidence: `packages/provider-bridge-acp/src/bridge/bridge.ts`,
  `selectAcpNativeModel` `shouldSetModel` gate; fake agent
  `src/bridge/fake-acp-agent.mjs` `session/set_model` handler rejects unlisted
  ids with `model not found`.
- Action: rework selection into "establish or fail": skip only when the
  requested id is already current; otherwise try `session/set_config_option`
  (when a model config option exists) then `session/set_model`; confirm via the
  returned config state when it reports the active model; accept an
  unverifiable success only when the id was advertised; otherwise throw an
  actionable error before any prompt.
- Risk: agents that silently accept `session/set_model` for unlisted ids with a
  bare success now fail construction instead of running the default model —
  intended per the task contract (no silent wrong-model spend).

## Entry 2 — conformance replay regression reshaped the fix

- Expected: strict "must confirm" selection to keep the recorded-conformance
  suite green.
- Observed: `bridge.recorded-conformance.test.ts` ("reproduces every recorded
  matrix cell", `runFirstPartyRecordedConformance` for `acp-cursor`) timed out
  at 240s under the strict rule; baseline without the change passes in ~14s.
- Evidence: every recorded acp-cursor cell sends `model: "auto"` with a
  `modelCli.selectFlag` launch spec. `rewriteAcpLaunchSpec` (provider-bridge
  replay harness) strips `modelCli`, so replay degrades the launch-flag
  selection into a native `{ modelId: "auto" }` selection against a recorded
  `session/new` catalog whose `availableModels` list parameterized ids
  (`default[]`, `grok-4.6[effort=high,fast=true]`, …) — `"auto"` is not listed.
  The strict build then issued an unrecorded `session/set_model`; the replay
  child answered generic `{ result: {} }` after its 5s stall, strict mode
  rejected the unconfirmed switch, `thread/start` failed, and each cell burned
  its 60s wait gates.
- Action: corrected the contract reading. ACP `session/set_model` returns no
  confirmation state on success — requiring positive confirmation makes any
  unlisted-but-valid id (e.g. Cursor's `auto`, only reachable via launch flag)
  unselectable and fails spec-conformant agents. New rule: always attempt
  establishment when the requested id is not already current; treat a success
  response as established UNLESS the returned config state reports a different
  current model (catalog contradicts the switch); collect all rejections and
  throw an actionable error before any `session/prompt`. Bare `{}`/`null`
  success is trusted per protocol.
- Risk: an agent that returns success from `session/set_model` without actually
  switching is non-conformant; that residual cannot be detected offline and is
  accepted. Recorded conformance passes again (~15s, one 5s replay stall per
  cell for the new unrecorded `session/set_model`).
- Deviation for parent: the recorded matrix encodes the old silent-skip. The
  new in-session `session/set_model` request has no recorded expectation, so
  each acp-cursor replay cell pays the replay child's 5s generic-answer stall.
  If tighter replay fidelity is wanted, the parity harness/recordings
  (packages/provider-bridge-protocol) need a `session/set_model` answer —
  outside this worker's scope.

## Entry 4 — review correction for authentication during selection

- Observed: an ACP `session/set_model` response with code `-32000` and message
  `Authentication required` was converted to a plain rejection string. When
  selection exhausted its methods, the resulting generic error lost the
  bridge's `authRequired` recovery metadata and suggested changing models.
- Action: propagate the typed ACP auth response from model selection so the
  existing outer recovery mapping retains `authRequired`. Ordinary selection
  errors still collect rejection details and can use the legacy fallback.
  Added wire-level tests for the auth response and for a config selection that
  reports the old model before a successful `session/set_model` fallback.
- Verification: `pnpm exec turbo run test --filter=@bb/provider-bridge-acp`
  passed (18 files, 330 tests); scoped Turbo typecheck passed.
