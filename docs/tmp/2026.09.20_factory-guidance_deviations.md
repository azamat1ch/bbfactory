# Factory guidance rewrite — deviations

Task: rewrite the operational orchestration skill as the single Factory skill
at `plugins/factory/skills/factory/` (name/id `factory`), plus developer
mapping docs. Worker clone only; no package/server/Team/backend changes.

## What landed

- `plugins/factory/skills/factory/SKILL.md` — short entry: chat/explore →
  draft/refine spec → direct-or-team implementation → proportionate
  review/fix → human approval.
- `references/`: `tasks.md` (spec/check/evidence/`bb factory` contract),
  `team.md` (folded Team skill + precedence/persistence), `delegate.md`
  (launch, risk-based supervision, steering, continuation, recovery, VCS
  observation, context inspection), `review.md` (lenses, prompt assets,
  optional depth recipes, `bb factory review collect`), `resources.md`
  (cooperative heavy-check safety), `configuration.md`,
  `runtime-contracts.md`.
- `prompts/`: all eight review assets retained and adapted — generic
  search/read tool names instead of `Grep`/`Glob`/`Read`, `json_repair`
  reference removed from `judge.txt`, C#-specific API names generalized in
  `probe-generic.txt`. Not byte-identical to the old bundle.
- `docs/product/factory-skill-mapping.md` — retained/moved/simplified/
  dropped ledger; `docs/product/provenance.md` notes the adapted prompts.

## Deviations and decisions

- `session-history.md` and `testing.md` were intentionally not carried into
  the operational skill (pending upstream surface; maintenance content).
  Disposition recorded in the mapping doc.
- Prompt files are adapted, not byte-identical — any preserved-hash bundle
  checks must be replaced (lead noted link/catalog checks will cover this).
- The universal first-minute check became risk-based supervision per spec
  `supervision`; "liveness ≠ understanding" retained.
- Review depth recipes retained as optional plans; composition examples use
  `bb factory execution` instead of `bb workflows`.
