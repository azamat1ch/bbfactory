## Official client semantics (primary source)

Installed Devin desktop app
`/opt/devin-3.10.31/resources/app/out/vs/workbench/windsurf-chat-client/index.js`
(version 3.10.31) contains the `exa.codeium_common_pb.PlanStatus`
constructor initializing `dailyQuotaRemainingPercent = 0`,
`weeklyQuotaRemainingPercent = 0`, `dailyQuotaResetAtUnix = 0`,
`weeklyQuotaResetAtUnix = 0`, and `PlanInfo` initializing
`hideDailyQuota = false`, `hideWeeklyQuota = false`. Its quota helpers
gate on `planInfo.billingStrategy === QUOTA`, skip hidden windows, and
treat `remaining <= 0` as exhausted. The workbench desktop main bundle
shows the same defaults and hides quota bars by those flags.

Source-backed rule adopted (parent-directed, replaces the earlier
conservative omission rule): ONLY when a real `planStatus` with a
confirmed `BILLING_STRATEGY_QUOTA` `planInfo` exists, an omitted
remaining-percent field is the protobuf default `0` → `usedPercent:
100`; `hide*Quota: true` windows are not emitted; missing or `0` reset
timestamps → `resetsAt: null`; valid nonzero Unix seconds → exact ISO
timestamp. Unknown/missing/non-quota plans remain `error`
(unavailable); malformed present values are `error`, never silently
dropped.

## Error semantics (verified live)

- Valid key + complete metadata → HTTP 200 JSON.
- Malformed or structurally invalid key (`invalid-test-key`,
  `devin-<random>`) → HTTP 400 `{"code":"invalid_argument"}`.
- Valid key + incomplete metadata → HTTP 400 `{"code":"invalid_argument"}`
  — therefore `invalid_argument` is a request/protocol rejection, NOT an
  auth failure (parent correction applied). Only HTTP 401/403 or a Connect
  `unauthenticated` code map to `expired`; everything else is a sanitized
  `error` (HTTP status + whitelisted Connect code only; response body,
  which embeds trace IDs, is never propagated; fetch exceptions surface a
  fixed message since raw error text can carry URLs/credentials; the API
  key appears only inside the request body, never in logs or results).
- Redirects are not followed (`redirect: "manual"`) so credentials are
  never forwarded to another origin.
- Reset timestamps are range-validated before `toISOString` (safe
  integer, `0 <= v <= 8.64e12`); out-of-range present values → `error`.

## Scope decisions (parent-directed)

- Emitted windows: only `dailyQuotaRemainingPercent` → "Daily quota"
  (`kind: "daily"`, `resetsAt` from `dailyQuotaResetAtUnix`) and
  `weeklyQuotaRemainingPercent` → "Weekly quota" (`kind: "weekly"`,
  `resetsAt` from `weeklyQuotaResetAtUnix`). `usedPercent = 100 −
  remaining` — the fields report remaining.
- NOT emitted: ACU (`acuConsumed`/`acuLimit`), all credit fields,
  `overageBalanceMicros`, `topUpStatus`, and `planEnd`-as-reset — their
  semantics were not live-verified on this account; no invented
  conversions, unlimited values, resets, or identities.
- `accountKey` = `devin:<orgId>:<userId>` only when both are present
  (daily/weekly quota may be per-seat; org alone could wrongly merge
  members). Otherwise `null`. Never email/token-derived.
- `plan` = `{id: teamsTier, multiplier: null}` where `teamsTier` comes
  from `planInfo.teamsTier` with fallback to the verified
  `userStatus.teamsTier` location; `planLabel` = `planInfo.planName`;
  `accountEmail` = `userStatus.email` when valid.
- No installer: `providerInstallation` stays unset.
  `AcpMaintenanceDialect.installer` is now optional and
  `canInstall`/`canUpdate`/install actions are gated on its presence so
  Devin's usage-only dialect cannot claim install capability (regression
  covered in `provider-maintenance.test.ts`; Cursor install/update
  behavior unchanged).
- Client identity sent: `ideName: "bb"`, `ideVersion: "0.0.0"`,
  `extensionName: "bb-provider-acp"`, `extensionVersion` = the bridge
  package's own version (`0.0.1`).
