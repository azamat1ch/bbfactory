# Factory living-spec integration notes

- The original draft task was attached to LifeOS. Execution uses a replacement task bound to the bbfactory directory; the preview remains historical.
- Native worker worktrees were provisioned with BB thread creation because Factory assign requires pre-existing environment IDs and the CLI has no standalone environment-create command. Worker threads are linked to the lead; no duplicate scheduler was introduced. Implementation lanes are provider controls, task/evidence backend and card UI.
- Verification and requesting agent review are separate actions. Verify executes declared checks; Request agent review sends a contextual request to the lead, which selects an eligible reviewer. This avoids an opaque button launching an unspecified team.
- The existing verify-bb inventory check fails before this feature with an unmapped browser CLI family. This baseline issue is not silently rebaselined.
- A separate QA checkout and fresh data store are used to avoid modifying the running BB instance. Linux browser checks do not establish iOS Safari or Electron behavior.

- A host reboot interrupted all three implementation threads. Their isolated worktree edits survived; all three original threads were resumed with remaining-work briefs after checking error state and preserved diffs. Temporary QA files were lost; subsequent logs use persistent thread storage.
- The first source dev launcher failed with EMFILE while creating Vite file watchers. Browser QA will use the optimized worktree launcher, avoiding source watchers.
- The three initially failing host checks could not reach the systemd user bus from the sandbox. The bus was healthy on the host; rerunning all seven host tests with host access passed. No containment checks were skipped or weakened.
- Integration caught and corrected an `agent-review` CLI collision with the existing `factory review collect` group. Composition tests now execute both entry points.
- The user stopped concurrent worker test/build suites because of host RAM pressure. All workers were instructed to stop, the lead cancelled the combined guidance/composition run, and the isolated QA app and browser were closed. A host process inspection found no remaining Turbo, Vitest or TypeScript jobs. The user then clarified that the lead should complete verification alone. Subsequent checks use serialized Turbo tasks and one Vitest worker with a bounded Node heap, with no competing worker suites.
- Static integration review extended disabled-global-default rejection to providers whose plugin is also unavailable. The regression covers both availability states and passed in the lead's serialized 71-test server run.
- Lead verification passed 54 Factory tests (including 21 UI and seven real host checks), 26 Provider Usage tests, 12 Factory composition/Team tests, nine guidance tests, and typechecks for the affected packages. The isolated optimized browser check also passed for 100-requirement pagination, method filtering, explicit start, grouped human controls and live linked check results (95 synthetic automated requirements accepted; five agent/human items stayed unverified). Provider disable persisted in Settings and excluded Claude Code from ordinary discovery while retaining its administrative entry. Worker completion alone was not used as acceptance.
- UI integration fixes keep expanded requirements across pagination and realtime updates, clear human selections even after content changes away and back, open relative artifact files through BB's existing file preview, and show acceptance counts by method.

- Browser screenshot inspection caught low-contrast artifact links using the background accent token; links now use the foreground token. Human criteria remain pending. iOS Safari and Electron were not exercised.
