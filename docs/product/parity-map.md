The primary delivery vehicle for the orchestration practices is an adapted **native BB skill bundle**: preserve upstream instructions, references and prompts nearly verbatim where compatible, and replace Porch calls with verified BB tools. Do not translate every instruction into TypeScript. Runtime work is limited to genuinely missing executable capabilities and invariants. The native foundation is a credible execution substrate, not near-complete orchestration. Reuse threads, providers and Workflows; add product contracts, supervision, review, inspection and resource policy around them. Workflows now provides the experimental discoverable execution seam described in [architecture](architecture.md). No mandatory Porch runtime, second scheduler, fixed lead provider, fixed worker hierarchy or compulsory delegation is proposed.

## Dispositions and measurement proposal

- **E — native-equivalent candidate/source-verified primitive only:** inspected native behavior offers a plausible equivalent; acceptance tests below are still required. This is not measured parity.
- **A — adaptation-required:** native primitives exist, but the full row contract needs integration, reconciliation or conformance work.
- **N — new-required:** a complete native deliverable was not established in this assessment; add it on native facilities. For guidance-layer rows this means packaging/adapting existing upstream text, not inventing new policy or implementing it in TypeScript. This does not claim a repository-wide proof of absence.
- **X — implementation-detail/not-applicable, proposed justification:** exclude only the named non-product detail. Related useful behavior remains mapped explicitly.

The 135-row inventory is weighted toward runtime details; row counts do not measure how much upstream instruction text is preserved or imply 135 TypeScript features. Review the skill section/prompt migration diff separately as well as this behavior ledger. Every original ID appears exactly once. Each table links upstream source and names BB evidence groups below. Row prose summarizes the adaptation; the original inventory remains the full bundled behavior checklist. A row passes only when **all useful sub-behaviors** pass, including negative cases and the applicable provider/platform matrix. Exact exit integers, filename layouts, XML syntax, shell transport and fixed historical model names are replaceable; partial failures, privacy, provenance, limits, ordering and safe recovery are not.

Propose excluding four whole rows: **RUN-17** (Porch Windows shim), **CFG-10** (internal test env spellings), **BND-08** (separate remote provisioning product), **BND-11** (upstream release plumbing). This gives **131 included rows, 121 required and 10 optional**, retaining original noncritical classification only for RUN-05, RUN-08, RUN-14, RUN-29, RUN-30, RUN-31, RUN-32, REC-19, BND-07 and BND-09. Optional does not mean deleted. Required + optional must reach **ceil(0.95 × 131) = 125**, and every one of the 121 required rows must pass. Without approval of these exclusions, retain **135 and threshold 129**, with the original 122 critical rows as the starting required set. Both denominator and classifications require independent review; neither is approved by this document.

Do not report 135 mapped rows as 100% implemented. No row receives tested credit here. Persist an evidence ledger per ID with requirement/spec version, implementation revision, exact content snapshot including new/dirty files, check definition/version, provider/model/reasoning/permissions/host, command, exit/result, logs, time and reviewer decision. Changed content/contracts invalidate affected evidence. Guidance rows need both prompt/template checks and observed scenario traces; prompt presence alone is not reliable agent compliance. A proposed exclusion needs an approved equivalence/scope rationale, not a fake passing test. Never shrink scope to hide an unsupported provider, an unavailable store or expensive review mode.

## Source findings that constrain the plan

1. **Writer safety is not supplied by persistence alone.** Workflows `runAgentCall` spawns workers with `environment: { type: "reuse", environmentId: run.environmentId }`. `stopChild` converts the SDK stop result to `undefined`, logs errors and returns. Retry paths can queue another attempt after a retryable error. The product must confirm old-writer termination and preserve ownership; existing recovery tests do not resolve this policy gap by their existence.
2. **Native staging needs deliberate composition.** Runtime tests explicitly exercise streaming pipelines without global stage barriers. Super/ultra require barriers. Build stages with settled native calls and explicit sequencing; do not flatten the upstream plans into one fan-out or use a streaming helper as if it were a barrier.
3. **Quota has a useful native base.** Usage normalization already merges known provider/account identities and prefers shared-scope observations, while retaining unknown identities separately. This does not establish shared quota identity across different harness/provider IDs, budgets/reserves or freshness policy. Keep source units and independent unavailable/error states.
4. **Guidance differs from enforcement.** Upstream delegate execution is permissive even for a read-only task; review-specific restrictions differ per harness. Native permission contracts may be stricter while preserving useful work. Prompt CDATA is not a security boundary. Repository text in `repository_facts` must be curated facts, not raw trusted instructions.
5. **Two upstream inventory claims need precise interpretation.** `mode_policy.py` accepts arbitrary `review-*` aliases as review, despite a broad unknown-mode rejection description; native policy should document/reject unknown modes explicitly. Upstream `_finalize` writes artifact copies before terminal metadata and the registry `final.txt` afterward; it does not make terminal metadata plus final file one atomic operation. The native contract must preserve recoverable final output and explicit availability, not reproduce that race.
6. **Native configuration is not automatically fail-closed.** `resolveConfiguredAcpAgents` warns and ignores invalid custom-agent JSON. Selected product profile configuration needs an explicit error instead of silently using another default. This is an adaptation of product selection, not a claim every upstream BB setting should change.
7. **Source identity and tests stay separate from current vendor promises.** This assessment is pinned local source analysis. It does not assert that current provider versions/accounts support the inspected flags/protocols. Version-specific implementation/live readiness reviews must verify their actual installed versions and primary upstream contracts.
